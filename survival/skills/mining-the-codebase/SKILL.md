# 采矿：系统性地理解陌生代码库

生存模式的第一法则：先采矿，再合成。采矿的目标不是「看看」，而是挖出足够支撑你安全合成（改动）的地图——入口、数据流、测试、约定。

## 挖矿流程

1. **先立坐标。** 读根目录清单：`package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` 等清单文件决定生态与脚本；`README*`、`docs/`、`CONTRIBUTING*` 决定入口与约定。用 fs/read 与 glob，不要一上来就 grep 全部。
2. **找到火把（构建与测试）。** 确认怎么构建、怎么跑测试、怎么 lint：清单里的 scripts / Makefile / 任务定义。先跑一次测试，看它是否本来就绿——这是你判断「我有没有把它弄坏」的基准线。
3. **沿矿脉开挖。** 从入口文件（main / index / 路由注册）沿调用链往下挖，而不是随机点开文件。每挖到一个关键模块，记下：它负责什么、被谁调用、依赖谁、有没有测试。
4. **用搜索当镐子，精准落点。** 明确了要改的功能后，用 `grep`/`glob` 精确找到符号、字符串、注册点，确认所有相关位置，避免「改了 A 忘了 B」。
5. **把地图写下来。** 重要发现写进笔记文件（如 `.notes/survival-log.md`）：结构草图、关键文件、构建/测试命令、风险点。背包（上下文）有限，地图可以随时回读。

## 采矿的纪律

- **先读后搜、先搜后改。** 顺序永远是：读清单 → 跑测试 → 沿调用链挖 → 精准搜索 → 才轮到改。
- **挖到矿脉的分叉就标记。** 遇到「这里看起来和需求有关」的旁路，先记进笔记，不要立刻偏离主线开挖。
- **问自己三个问题再收工：** 我知不知道入口在哪？我知不知道怎么验证改动？我知不知道哪里最可能被我弄坏？答不上来就继续挖。

## 产出

一次合格的采矿以一张可执行的地图结束：世界结构、验证命令、目标改动点、风险清单。把这张地图写进笔记，然后才开始合成。
