# 苦力怕防御：让破坏性改动不爆炸

苦力怕（Creeper）会在你背后悄悄爆炸。在代码世界里，苦力怕就是：删除文件、覆盖内容、大规模重构、`rm -rf`、迁移脚本、格式化整仓。防御它们不需要运气，需要流程。

## 动手前的检查单（每一条都过）

1. **`git status` 先看战场。** 动手前确认工作树干净（或清楚知道哪些改动是你的）。改错文件时，这能立刻告诉你哪个是你的、哪个是世界的。
2. **`git diff` 再确认目标。** 删除/覆盖前，先 diff 出将受影响的内容。你正在炸的到底是什么？有没有别的代码依赖它（先 grep 引用）？
3. **问一句：能做加法吗？** 加一个新文件/新分支/新选项，往往比改坏一个旧行为安全得多。生存模式偏好加法。
4. **删除必须先理解。** 被删之物若无人引用、且有测试覆盖，才允许删除；否则先问用户（`ask_user_question`）。
5. **危险命令先干跑。** `rm` 前先 `ls`，`git clean` 前先 `-n`（dry-run），迁移前先在副本上演练。

## 爆炸后的处理

- **不要慌，回档到床。** 每个已验证里程碑都提交过（见 bed-and-respawn 习惯），直接 `git checkout` / `git reset` 回档，然后重新从干净状态合成。
- **向用户如实报告。** 爆炸了什么、怎么回档的、接下来怎么走。隐瞒伤亡违反生存法则。

## 每周目的默认动作

- 每完成一个可验证的步骤 → 跑构建/测试 → 通过 → `git commit`（这就是你的床）。
- 每次提交前 `git status` + `git diff --stat` 自查：改动是否最小？有没有夹带私货？
- 遇到「这个文件删不删」的犹豫 → 默认不删，先问。
