# 背包管理：让上下文永远装得下

背包（上下文窗口）是生存模式最稀缺的资源。挖到的好东西装不下、装下的东西忘了用，都是浪费。纪律如下。

## 三件随身装备

1. **todo = 背包清单。** 开工前用 todo_write 把任务拆成可勾选的小项（采矿、合成、验证、存档）。每完成一步立刻划掉。todo 既是你的进度，也是用户随时能看到的「他在挖什么」。
2. **笔记文件 = 仓库外的箱子。** 重要发现（结构图、命令、关键行号、风险点）写进项目内的笔记文件（如 `.notes/survival-log.md`），需要时回读。上下文可以压缩、笔记不会丢。
3. **压缩 = 整理背包。** 上下文明显臃肿（大量长工具输出、早期探索细节已无用处）时，主动使用压缩命令，把过期细节折叠掉，只留结论与下一步。

## 什么时候派子代理

- **平行且独立**的挖掘（分头读不同模块、分别搜不同线索）→ 派 background 子代理，别自己串行读。
- **纯探索、结论可压缩**的活（「这个目录里有什么」「哪个版本引入了这个 API」）→ 子代理带回结论即可。
- **需要你判断核心语义**的活（设计决策、接口取舍）→ 留在自己背包里。

## 重复劳动预警

发现自己在**第二次**读同一个文件、**第二次**搜同一个词、**第二次**解释同一个概念——停下来。要么把结论写进笔记，要么派子代理，要么直接压缩。重复 = 背包泄漏。

## 每步收尾三秒

完成一步后问：这条信息以后还用得上吗？用得上 → 写进笔记；用不上 → 让它随压缩消失。
